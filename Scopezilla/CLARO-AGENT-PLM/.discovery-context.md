1. O que é o PLM (um parágrafo)

PLM POC = **pipeline de validação de catálogo de produtos** nativo Salesforce para a Claro. Uma **Demanda** (Demanda\_\_c) é um lote de validação que agrupa muitos **Itens** (Item\_Demanda\_\_c) mapeados a partir de um layout CSV corporativo. Cada item carrega TIPO\_PRODUTO\_\_c ∈ {Fone, BL, TV} que roteia para o conjunto de regras do tipo de produto. As regras são **compiladas por LLM num AST** (Plm\_Rule\_Spec\_\_c.Spec\_JSON\_\_c) e executadas por um **AST walker puro-Apex** (PlmRuleSpecEvaluator). Demanda agrega-os e um **prompt template Einstein** produzindo uma narrativa de diagnóstico em HTML. Dois agentes **Agentforce** Employee conduzem o fluxo: **Admin** (compile-time: compilar/recompilar/status) e **Ops** (runtime: importar CSV / avaliar / diagnosticar).

2.2 Escopo de solução (capacidades funcionais)

* **3 tipos de produto** validados: Fone, BL, TV (o catálogo BRE legado tinha 127 regras; os specs Lane B são compilados por LLM por productType|ruleId).
* **3 canais de severidade**: ERRO (bloqueia Pre\_Aprovado), AVISO, INFO.
* **Seguro para grande volume de dados (LDV)**: cursor byte-offset no CSV + cursor por-Id na avaliação quebram os caps de OFFSET-2000 / CPU-síncrono-10s.
* **Autoria de regras self-service** via agente Admin (compilar/recompilar drifadas/status) sem redeploy.
* **Loop de agente ponta-a-ponta**: agente Ops importa → avalia → diagnostica; loop de correção realimenta a reavaliação.

2.3 Escopo de arquitetura (tenets de design travados)

* **Async-first** em tudo (chains Queueable/Batch; lane síncrona só enfileira, 0 callouts LLM).
* **Cache de quatro tiers, sem Platform Cache** (Map estático → Plm\_Rule\_Spec\_\_c durável → Plm\_Rule\_Catalog\_Cache\_\_c → LDS). Restrição: STORM\_PLM/Ibuy **não** alocam partição de Platform Cache.
* **Progresso baseado em PE** (publish append-only + rollup M-D) — sem contenção de hot-row; recordChunk R-M-W como fallback.
* **Idempotente + replay-safe** (Spec\_Key\_\_c + Source\_Hash\_\_c; token de idempotência SHA-256 no chunk log).
* **DLQ-first** no tratamento de falhas + recuperação de chain-death (Finalizer + Reaper + BatchApexErrorEvent).
* **JSON como source-of-truth** dos verdicts; os campos shadow \*\_BRE\_\_c são "zombie" (mantidos, não-autoritativos).
* **Envelope de governor orçado por lane** (sync 10k CPU, async 60k CPU, PE 250k/dia).

## 3. PREMISSAS — orientadas aos templates de carga e ao catálogo de regras

As premissas estão organizadas por eixo: \*\*(A) Template de carga (CSV)\*\* — o contrato de entrada de dados; \*\*(B) Catálogo de regras\*\* — o contrato de definição/compilação das regras; \*\*(C) Plataforma\*\* — pressupostos técnicos que sustentam A e B.

### 3.A — Template de carga (CSV de Demanda)

| # | Premissa | Fonte / consequência se falsa |

|---|---|---|

| TC1 | \*\*Template canónico de carga\*\* = Solução baseada nos arquivos recebidos de Carga de Import e Regras de avaliação|

| TC2 | \*\*`TIPO PRODUTO ∈ {Fone, BL, TV}` é a routing key\*\* — decide qual subconjunto do catálogo roda no item. | Blank → INFO sintético em todas as linhas. Mistura de tipos no mesmo CSV é aceita (`ProductTypes\_Mistos`). |

| TC3 | \*\*Contrato de aceite do ficheiro\*\*: UTF-8; LF (CRLF aceito); aspas duplas p/ vírgula ou quebra literal; decimal ponto (`49.50`); data `yyyy-MM-dd` (preferível) ou `dd/MM/yyyy`; boolean lowercase `true\|1\|sim\|s`; checkboxes S/N normalizados (`normalizeSimNao`). | Fora do contrato → aviso `Linha N — <campo>: invalid` ou coerção errada. |

| TC4 | \*\*Limites de carga\*\*: ≤ 6.000.000 chars (`PLATFORM\_MAX\_STRING\_CHARS`, reject acima → split em uploads); ≤ 10.000 linhas em modo síncrono (`MAX\_LINHAS`) — acima dispara chain assíncrona (cursor byte-offset resumível em `Plm\_Csv\_Import\_State\_\_c`). | Ficheiro grande sem o caminho async → estouro de CPU/heap. |

| TC7 | \*\*Mapeamento coluna → campo é 1:1\*\*; colunas não-mapeadas (`CSV\_COL\_IGNORADA`: `ID DEMANDA`, `POSSUI ANEXO`, `CRIADO POR`, `DATA CRIAÇÃO`) são descartadas em silêncio (útil p/ CSV legado). | Coluna duplicada → última vence (sem proteção). |

| TC8 | \*\*FLS de carga\*\*: campos de destino exigem create-access no permset `Validacao\_Engine\_Access` (`isCreateable()` no controller). | Sem FLS → linha rejeitada na importação. |

### 3.B — Catálogo de regras

| # | Premissa | Fonte / consequência se falsa |

|---|---|---|

| CR1 | \*\*Catálogo-fonte = DSL pt-BR\*\* (uma regra por bloco), chaveado por `productType + ruleId`. | É a entrada humana; \*\*não\*\* se escreve o AST à mão. |

| CR2 | \*\*Compilação é por LLM\*\*: `PlmRuleSpecCompilerService` chama o Prompt Template `PLM\_Rule\_Compiler` (Einstein) → emite AST → `upsert Plm\_Rule\_Spec\_\_c (Spec\_Key\_\_c='productType\|ruleId', Spec\_JSON\_\_c=ast, Status\_\_c='Active')`. | Sem `applicationName` (P-C2) → falha de compilação. |

| CR3 | \*\*Avaliação é determinística, sem LLM\*\* — `PlmRuleSpecEvaluator` percorre o AST → `Verdict ∈ {PASS, FAIL, NOT\_APPLICABLE, NOT\_COMPILED, EVAL\_ERROR}`. `expected="FAIL"` (fail-on-true: match no predicate ⇒ violação). | Spec não-compilada ⇒ `NOT\_COMPILED` (não trava o item silenciosamente). |

| CR4 | \*\*Identidade da regra\*\*: `ruleId` regex `^REG-\d{3}$`; `uniqueKey` `^(Fone\|BL\|TV):REG-\d{3}$`; `severity ∈ {ERRO, AVISO, INFO}` (só `ERRO` bloqueia `Pre\_Aprovado`). Numeração independente por ProductType. | `uniqueKey` é prefixo em `Motivos\_BRE\_\_c`; colisão quebra rastreabilidade. |

| CR5 | \*\*Detecção de drift por `Source\_Hash\_\_c`\*\*; recompila drifadas via agente `Agentforce\_PLM\_Admin` (capability bulk, `dryRun=true` default) sem redeploy. Spec com schema inválido \*\*não\*\* vira `Active` (fica `Drift`/`Failed`). | Idempotência: `Spec\_Key\_\_c + Source\_Hash\_\_c` evita re-LLM redundante. |

| CR6 | \*\*Lookups do catálogo resolvem em compile-time, não em runtime\*\*: famílias `Aux\_\*\_\_mdt` (5, 66 linhas seed) + Decision Tables `PLM\_RuleCatalog` + `PLM\_FieldRuleMapper`. | Runtime só percorre AST puro (CPU < 50 ms/record). |

| CR7 | \*\*Operador fora da allowlist de 21\*\* exige extensão de schema (patch em `PlmRuleSpecSchemaValidator` + `PlmRuleSpecEvaluator`) — hand-off BA → Dev. | Sem extensão → validação rejeita a regra. |

### 3.C — Plataforma (sustenta A e B)

| # | Premissa | Fonte / consequência se falsa |

|---|---|---|

| PC1 | \*\*Einstein / Prompt Templates exigem `additionalConfig.applicationName='PromptTemplateGenerationsInvocable'`.\*\* | Fix D1; sem isso → `INTERNAL\_ERROR` org-wide. Obrigatório em todo `generateMessagesForPromptTemplate` (compile + diagnóstico). |

| PC2 | \*\*Sem partição de Platform Cache\*\* em STORM\_PLM / Ibuy. | Cache via Map estático + `Plm\_Rule\_Spec\_\_c` durável + SOQL em `Spec\_Key\_\_c`. |

| PC3 | \*\*Tunables são CMDT-driven\*\* (`Plm\_Tenant\_\_mdt`, `Plm\_Compile\_Config\_\_mdt`) — flipáveis em runtime, sem redeploy (ex.: `Compile\_Mode\_\_c` queueable![:left_right_arrow:](data:image/png;base64...)batch; chunk size; teto de CPU). | Premissa de operabilidade do catálogo + carga. |

| PC4 | \*\*Quick-deploy é rejeitado\*\* em ambos os orgs (`CannotQuickDeployError`); deploys vão diretos com `--test-level RunSpecifiedTests`. | Status cross-org §0. Auto-rollback em falha de teste preservado. |

| PC5 | \*\*Campos required / Master-Detail NÃO podem aparecer em `<fieldPermissions>` do permset.\*\* | Lição D3/D4; auto-granted via objectPermissions, FLS explícito = erro de deploy. |

## 4. FORA DE ESCOPO — explicitamente NÃO neste POC

### 4.2 Fora de escopo de solução

- Tipos de produto \*\*além de Fone / BL / TV\*\*.

- \*\*Ingestão Bulk API 2.0\*\* para CSVs > 6 MB (backlog W3.1).

- \*\*Avaliador de regras Batchable\*\* para demandas > 50k itens (backlog W3.2); avaliação atual é Queueable Id-cursor.

- \*\*Roll-ups Apex custom\*\* para os 6 campos summary de `Demanda\_\_c` (backlog W3.3) — ainda roll-up nativo/derivado de JSON.

- \*\*Sweep do import-state CSV\*\* (`Running`→`Failed` em heartbeat obsoleto) — backlog W3.5, não construído.

- Hardening de produção: \*\*split de permset\*\* (Operator vs Admin), caps de complexidade regex (Sec R5), postura de segurança pré-prod — todos adiados (backlog W3.4/W3.8).

### 4.3 Fora de escopo de arquitetura

- \*\*Platform Cache\*\* como tier (premissa P2 proíbe).

- \*\*Multi-org / packaging\*\* (managed package, namespace) — `namespace: ""`, single-tenant trial.

- \*\*Integração cross-system\*\* (MuleSoft, APIs externas, CDC para warehouse) — nenhuma no PLM; CSV é a única ingestão.

- \*\*Plataformas de dados não-Salesforce\*\* (Data Cloud / Snowflake / dbt) — fora do POC.

- \*\*Streaming em tempo real para consumidores externos\*\* — uso de PE é interno (progresso de compile) apenas.
